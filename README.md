# JC Pit

Первая рабочая итерация сайта **Jerusalem Chinaski**. **JC Pit** — название проекта и пространства бренда. Статический сайт без сборки, пакетов и серверной части; рассчитан на дальнейшие правки.

Целевое тестовое размещение: GitHub Pages, репозиторий [`tema-git/jc-pit`](https://github.com/tema-git/jc-pit), адрес [`https://tema-git.github.io/jc-pit/`](https://tema-git.github.io/jc-pit/). Публикация и её проверка выполняются владельцем основной задачи; наличие адреса в этом документе само по себе не подтверждает успешное развёртывание.

## Что есть в текущем коде

- Закреплённая шапка с доступной на телефоне кнопкой «Контакты» и раскрывающейся навигацией.
- Крупный первый экран с боковой фотографией высоких ботинок и локальными шрифтами Instrument Serif / Golos Text.
- Рассказ о московской мануфактуре и индивидуальном изготовлении.
- 10 изделий, фильтры «Все изделия / Обувь / Объекты», диалоги с доступными фотографиями и переходом к обсуждению выбранной модели.
- Атмосферный фильм из предоставленных материалов. По умолчанию показывается постер; движение включается отдельной кнопкой.
- Самостоятельный интерактив «Свой ракурс»: выбор фотографии, фиксация результата и повтор.
- Ответы о начале заказа, стоимости и прямой продаже.
- Реальная ссылка на почту и Instagram, а рядом — честная локальная тестовая форма с валидацией, состоянием результата и повтором.
- Ограниченные реакции изображений на указатель, эффекты прокрутки, мобильные состояния и `prefers-reduced-motion`.

Проверочные данные формы не отправляются и не сохраняются в `localStorage`, cookies или на сервере. При успешной локальной проверке имя, контакт и пожелания очищаются. Кнопка письма открывает почтовое приложение через `mailto:`; отправляет письмо сам посетитель. Подключённого обработчика заявок и реального оформления заказа нет.

## Запуск локально

Открывать через HTTP-сервер, поскольку подробности изделий загружаются из `products.json`. Прямое открытие `index.html` через `file://` не подходит для проверки каталога.

Из папки проекта, при наличии Python 3:

```sh
python3 -m http.server 4173
```

Затем открыть [`http://localhost:4173/`](http://localhost:4173/). Установка зависимостей и сборка не требуются. Можно использовать любой другой статический HTTP-сервер с корнем в этой папке.

## Структура

| Файл / папка | Назначение |
| --- | --- |
| `index.html` | Семантическая структура, 10 карточек, тексты, форма и оболочка диалога |
| `style.css` | Токены, локальные шрифты, адаптивность, selection, эффекты и reduced motion |
| `app.js` | Меню, фильтры, диалог и галерея, локальная форма, выбор ракурса, фильм и движение секций |
| `products.json` | Данные диалогов: стабильные id, имена, годы, категории, фотографии и описания |
| `assets/` | Оптимизированные фотографии, знак, фильм, иконка и шрифты с лицензиями |
| `materials/` | Исходники, инвентаризация Яндекс Диска, контактные листы и соответствие оригиналов веб-файлам |
| `DESIGN.md` | Бренд, направление, точные референсы, карта взаимодействий и все 11 постоянных требований |
| `robots.txt` | Ограничение индексации тестовой версии; в HTML также есть `noindex,nofollow` |

Карточки в HTML и записи в JSON связаны по `data-product` / `id`. При добавлении или переименовании изделия обновлять оба места, фильтр категории и список интересов формы. Функция `selectInterest()` использует точное совпадение имени со значением `option`.

Идентификаторы текущих моделей: `zip-2026`, `shoes-2026`, `wholecut-2025`, `high-2025`, `boots-2025`, `shoes-2025`, `duffel`, `gloves`, `wallet`, `dice`. Категории: `shoes` и `objects`.

Все ссылки на локальные файлы относительные: это важно для публикации в подпапке `/jc-pit/`. Не заменять их путями от корня домена `/assets/...` без отдельной настройки размещения.

## Дальнейшие итерации

Сначала читать `DESIGN.md` и текущую реализацию. Сохранять различие между брендом Jerusalem Chinaski и проектом JC Pit, монохромную палитру с серебряными главными действиями и все 11 правил пользователя. В этой итерации пользователь попросил базовый набор возможностей; новые большие функции добавлять по дальнейшим указаниям.

Небольшие правки текста не требуют установки UI-библиотек или нового дизайна. При существенном редизайне использовать закреплённый в `DESIGN.md` workflow Refero / 21st / MotionSites и записывать конкретные влияния и проверенные состояния.

Для изменения материала сохранять источник и соответствие веб-файлу; не подменять реальные фото товара. Не хранить в публичном репозитории учётные данные, HTML-копии закрытых страниц Tilda, личные данные посетителей и временные закрытые ссылки.

Тестовый сайт намеренно закрыт от поисковой индексации. Перед запуском на основном домене отдельно решить вопрос индексации, метаданных, финальных текстов и реального обработчика формы. Не менять честное сообщение об эмуляции, пока серверная отправка действительно не подключена и не проверена.

## Проверка перед публикацией

Это список необходимых действий, **не список уже пройденных проверок**. Итоговую проверку и отчёт ведёт исполнитель публикации.

1. Открыть по HTTP на широком экране, около 768 px, 390 px и 320–360 px. Просмотреть всю страницу: фото, переносы, контраст, загрузку локальных шрифтов, отсутствие горизонтальной прокрутки. Проверить размеры кнопок и подписей по `DESIGN.md`.
2. Прокрутить до конца и обратно: шапка и «Контакты» остаются доступны, якоря и фокус не скрываются под ней. На телефоне открыть и закрыть меню, перейти по ссылке, закрыть Escape и нажатием вне меню.
3. Выделить текст на чёрном и светлом фоне: меняется цвет букв, фон выделения прозрачен, копирование работает. Проверить заметные реакции в нижних блоках; ссылка, кнопка и поле не смещаются.
4. Нажать все фильтры: ожидаются 10 / 6 / 4 карточки, соответствующий счётчик и выбранное состояние. Открыть каждое изделие, пройти все имеющиеся фото кнопками и ← / →, закрыть кнопкой, Escape и нажатием снаружи. Проверить возвращение фокуса.
5. Быстро переключать ракурсы и открывать разные изделия: запоздавший ответ загрузки не должен заменить текущую фотографию. Проверить понятное состояние ошибки для недоступного JSON или изображения и повтор после восстановления.
6. Полностью пройти «Свой ракурс» мышью, касанием и клавиатурой: каждый из трёх вариантов → фиксация → результат → сброс → повтор. Проверить быстрые действия и переход к контактам с выбранной моделью.
7. Фильм не играет до явного включения. Проверить запуск, остановку, уход секции из видимой области и переключение вкладки. При ошибке видео постер и управление должны оставаться понятными.
8. Отправить пустую форму и некорректные значения: видимые ошибки, `aria-invalid`, фокус на первом неверном поле. Затем проверить имя и корректные email / телефон / @ник, локальный результат, очищение личных полей и повтор. Убедиться в отсутствии сетевой отправки и хранилища введённых данных.
9. Включить `prefers-reduced-motion`: остановлены параллакс, масштабирование и плавный скролл; содержимое, фильтры, диалог, интерактив и форма доступны. Проверить клавиатурный фокус, действительные email/Instagram-ссылки, отсутствие ошибок консоли и битых ресурсов.
10. После публикации повторить основные сценарии на реальном адресе GitHub Pages, включая пути ассетов в `/jc-pit/`, JSON, видео и мобильную шапку. Только после этого считать тестовый адрес проверенным.
