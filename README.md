# JC Pit

Сайт бренда **Jerusalem Chinaski**. **JC Pit** — название проекта. Статический сайт без сборки и серверной части, рассчитанный на дальнейшие итерации.

Тестовый адрес: [JC Pit](https://tema-git.github.io/jc-pit/). [Репозиторий tema-git/jc-pit](https://github.com/tema-git/jc-pit); GitHub Pages публикует ветку main из корня. Авторизация пользователя на обновление этого тестового адреса действует. Основной домен hjcpit.ru и исходный проект Tilda не изменяются. Фактические результаты последней проверки и публикации — в QA.md; этот README не подтверждает прохождение проверок.

## Текущее направление

27.10.2026 пользователь попросил сделать макет как в существующей Tilda, добавив smooth, анимацию и интерактив. Исходная композиция теперь приоритетна: лесной DIVE IN → CHOICE с фирменным знаком и двумя фото → отдельные CATALOG и ARCHIVE. Цветные исходные фотографии остаются на чёрном фоне, типографика — локальные Montserrat и Source Code Pro. Предыдущая редакционная одностраничная версия с огромным Instrument Serif и светлой сеткой не задаёт текущий макет.

Сохраняются общие требования: закреплённая шапка и заметные «Контакты» на телефоне, серебряные главные действия, винное выделение букв без подложки, нативный крест с короной в отдельных декоративных зонах, реакции на курсор и скролл, reduced motion. Ряды каталога поддерживают нативный свайп, кнопки и клавиатуру; изделия открываются в диалогах с галереями. В каталоге остаётся компактный отдельный интерактив «Рассмотреть детали» с результатом и повтором.

Форма демонстрационная: данные не отправляются, заказ не создаётся. Введённые значения не сохраняются в localStorage, cookies или на сервере; после успешной локальной проверки личные поля очищаются. Реальное обращение доступно через `mailto:` — письмо отправляет сам посетитель. Не подключать обработчик и сохранение данных без отдельного запроса.

## Запуск локально

Открывать через HTTP, поскольку подробности изделий загружаются из JSON. `file://` не подходит для полноценной проверки.

Из папки проекта, при наличии Python 3:

```sh
python3 -m http.server 4173
```

Открыть [http://localhost:4173/](http://localhost:4173/). Подойдёт любой статический HTTP-сервер с корнем в этой папке; установка пакетов не требуется.

Все локальные URL относительные: сайт опубликован в подпапке `/jc-pit/`. Не менять их на `/assets/...` без отдельной настройки размещения. Карточки в HTML и записи JSON связаны по `data-product` / `id`; при изменении изделия синхронизировать id и опции формы.

Каталог содержит 10 моделей: `zip-2026`, `shoes-2026`, `wholecut-2025`, `high-2025`, `boots-2025`, `shoes-2025`, `duffel`, `gloves`, `wallet`, `dice`. Их категории — `shoes` и `objects`. Раздел одежды каталога воспроизводит сообщение оригинала; вымышленные карточки туда не добавляются. Ещё 13 архивных записей имеют отдельные id с префиксом `archive-`; архив использует категории `shoes`, `garments`, `objects`, `other` и `archive`. Точное соответствие исходным карточкам хранится в materials.

## Следующие изменения

Сначала читать DESIGN.md и текущую реализацию. Сохранять различие бренда и проекта, макет Tilda, все 11 постоянных правил и приоритет телефона. Refero / 21st / MotionSites остаются источниками движения и качества; явный запрос пользователя к композиции главнее внешних референсов. Маленькая текстовая правка не требует нового дизайна или UI-библиотеки.

Кнопку «Включить движение» не возвращать. Видео должно оставаться немым, с постером и воспроизведением только по видимости/активности вкладки, без reduced motion и экономии трафика. Не повторять один и тот же обувной кадр в двух местах одной композиции: для нижнего бокового ракурса есть `hero-zip-boots-walk.webp`.

Перед запуском на основном домене отдельно согласовать индексацию, метаданные, окончательные тексты и реальный обработчик формы. Пока его нет, сохранять честное сообщение об эмуляции.

## Проверка перед публикацией

Это необходимые действия, **не уже пройденные проверки**. Итоговый отчёт ведёт исполнитель публикации в QA.md.

1. Открыть все четыре страницы по HTTP на широком экране, около 768 px и провести три мобильных прохода 320 / 390 / 430 px, дополнительно проверить горизонтальную ориентацию. Проверить исходный порядок, фото, переносы, контраст, локальные шрифты и отсутствие горизонтальной прокрутки страницы/диалога. Горизонтальные ряды остаются внутри своей области.
2. Пройти DIVE IN → CHOICE → CATALOG / ARCHIVE и обратные переходы. Прокрутить каждую страницу: закреплённая шапка и «Контакты» доступны; якоря и фокус не скрыты под шапкой. Проверить мобильное меню, переход по ссылке, Escape и закрытие снаружи.
3. Проверить выбор текста на тёмной поверхности и серебряной кнопке: винные буквы, прозрачный фон, копирование работает. Проверить курсор только в разрешённых декоративных зонах и неподвижность ссылок, кнопок, полей при движении и скролле.
4. Пройти каждый горизонтальный ряд мышью, касанием и клавиатурой до обоих краёв, проверить кнопки и счётчики, быстрые повторные действия. Сравнить порядок, названия, описания и цены с подтверждённым Tilda-источником.
5. Открыть все модели, пройти реальные ракурсы кнопками и ← / →, проверить закрытие кнопкой, Escape, нажатием снаружи и возврат фокуса. Переход к контактам должен выбирать нужную модель. Проверить ошибку загрузки JSON/фото и отсутствие запоздавшей замены фото при быстром переключении.
6. Полностью пройти «Рассмотреть детали»: каждый вариант → фиксация → результат → сброс → повтор мышью, касанием и клавиатурой. Проверить быстрые действия и отсутствие повторного кадра в нижнем боковом ракурсе.
7. Убедиться, что кнопки «Включить движение» нет. Проверить автоматическое немое видео, остановку вне экрана и в скрытой вкладке, возвращение к экрану, постер при отказе/ошибке, reduced motion и экономии трафика.
8. Проверить пустую форму и неверные значения: понятные ошибки, aria-invalid и фокус на первом неверном поле. Затем имя + корректные email / телефон / @ник → честный локальный результат → очищение личных полей → повтор. В сети и хранилищах не должно быть отправки/сохранения данных.
9. Включить prefers-reduced-motion: декоративное движение, параллакс, видео и плавный скролл остановлены; содержимое, меню, ряды, галереи, интерактив и форма доступны. Проверить клавиатурный фокус, почту/Instagram, отсутствие битых ресурсов и ошибок консоли.
10. После публикации повторить основные сценарии на GitHub Pages, включая все страницы и пути ассетов/JSON в `/jc-pit/`, мобильную шапку, форму и галерею. Только затем описывать опубликованную итерацию как проверенную.
